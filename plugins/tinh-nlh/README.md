# Nếp

Nếp là nơi cả công ty NhiLe giao việc, theo dõi việc và ký duyệt. Cài một lần, đăng nhập bằng email công ty.

- Xem việc: hỏi Claude "việc của tôi hôm nay?" hoặc gõ `/work`. Ở Claude Code và Cowork, mở phiên mới là Claude tự kể.
- Giao việc: "Giao cho chị Thùy: …, xong khi …" hoặc `/assign`.
- Ký: "tôi ký" hoặc `/sign`.

Cài trong Claude Code: dán vào Claude Code một câu, Claude tự làm hết, bạn chỉ đăng nhập:

```
Cài Nếp cho máy này theo https://raw.githubusercontent.com/NLH-GOVERNANCE/claude-plugin/main/SETUP.md
```

Cài trên claude.ai và bật Loa: xem README ở gốc repo `NLH-GOVERNANCE/claude-plugin`.

## For maintainers

Technical name `nlh` (old name `tinh-nlh`, migrated by `renames` in the marketplace), display name Nếp. Contents:

- connector `nep` (`https://mcp.nlh.vn/mcp`, scoped name `plugin:nlh:nep`, tools `mcp__plugin_nlh_nep__…`; since 0.22.0, anh Sơn 26/10): install the plugin and Nếp is there, sign in once in the browser (`/mcp`, `plugin:nlh:nep`). On a machine it wins over a Nếp connector of the account at the same URL, which Claude Code then hides. In cloud sessions it can never sign in, but the proxy rewrites the account connector's URL, so the account connector stays and carries Nếp there; the session-start line tells Claude not to ask for sign-in in the cloud. Hooks call `plugin:nlh:nep` first, then the account connector by the names it takes (`claude.ai Nếp` on a machine, `Nếp` in the cloud, the older `nhile-governance`, `NhiLe Governance`, and the company connector id `3398cc99-b4dc-41bd-8007-bd4b6792d5cb`, the name it takes in sessions made by `create_session` and in the desktop app). Setup steps for Claude: `SETUP.md` at the repo root;
- skill `nep`: the first turn of every conversation calls `my_context` (who you are, your cells, open projects, work waiting, work assigned) and summarises it in plain Vietnamese;
- seven commands: `/nlh:work` (inbox), `/nlh:assign` (assign work to a cell), `/nlh:resume` (resume a piece of work), `/nlh:handoff` (write a handoff), `/nlh:sign` (tickets waiting for your signature), `/nlh:no-save` (stop saving this session to the chat store), `/nlh:speaker` (turn on Loa on this machine: the "Loa tỉnh NhiLe" desktop icon). In the Claude app and on the phone type `/work`, `/assign`, `/sign` (or say "xem việc của tôi", "giao việc", "tôi ký");
- Loa, the speaker on the machine (channel `speaker` and its launchers in `speaker/`, Windows and macOS; Claude Code only, only when opened from the Loa icon): reads the user's new work from the hub every 15 seconds with a private key and tells the session seated at each cell in one sentence, by the session id that session reported; never resumes a stopped session and never opens a new one (no `claude --bg`, ticket 3a65c3bd): with no session at the cell it prints one line and the work stays in the inbox; skips work held by another machine or a cloud session (one item, one place, D-0065); after more than 2 hours away prints one line with the count instead of the backlog; writes one ledger row per delivery, no content. Reminds the same session once when an item is still in the feed after 30 minutes and nobody holds it; holds a new answer 2 minutes and sends it only if still in the feed; skips work a cell opened for itself. Skill `speaker-loop` instructs the Loa session (named apart from the `speaker` command, which wins a shared name). The hub calls Loa tower: tower = speaker. Setup: root README, "Bật Loa trên máy";
- hooks (Claude Code and Cowork only): at session start, print one line telling Claude to call `my_context` first, with this session's id and name; after `/clear` or compaction, call `my_context` through the signed-in connector and load the result; at the end of each turn and when the session closes, call `report_session` with the session id and status, so Loa knows which session sits at which cell. The start line also says to read `village_rules` (luật làng) before any work; when the user's prompt sounds like a correction (signals in `hooks/correction-signals.json`, matched without diacritics), one line of context says to fix the work first, then add the lesson to luật làng if it holds for every trade, or to the villager's own playbook if not; and when what the user corrects or rejects is the result of a Nếp work item, to record that on the item as a check (rejected or edited, said by the user, the user's words quoted). Hooks hold no token and send no chat content. Chat saving: when the user sends a prompt and when Claude finishes answering, call `save_chat` with that turn (never tool results); the store sits outside the ledger, only keeps sessions that really use Nếp (a Nếp tool other than the opening `my_context`, reported by the PostToolUse hook; or seated at a cell), long term; phone numbers, emails, ID numbers and addresses are encrypted; turns with keys or about money, contracts, HR, customers or children are not stored verbatim; no delete button, soft delete only.
- local gate (Claude Code only): before a Bash or PowerShell command runs `git commit` or `git push` in a repo of NLH-OS, NLH-GOVERNANCE or NLH-NEDU-*, `gate/hook.mjs` runs what Review would fail on: the counted rules of `gate/rules.mjs` in NLH-OS/api (fetched with the user's `gh` from `main`, cached 6 hours in `~/.tinh-nlh/gate`, never copied into the plugin), the repo's `test:fast` script if its root `package.json` has one, and the repeated errors in `gate/repeated-errors.json` (one check per line; the weekly repeated-errors round adds lines). A failure denies the command with one line per finding. After a push that passed, Claude writes one fact line on its ticket. Other repos and other commands are untouched; the hook failing never blocks.
- auto-push (Claude Code only): after a Bash or PowerShell `git commit`, `hooks/autopush-hook.mjs` starts `hooks/autopush-worker.mjs` in the background. Scope, fixed (anything else is left to push by hand): it pushes the branch ONLY when all of these hold: (1) the branch is not dev, main, master, release/* or hotfix/*; (2) origin has exactly one fetch url and one push url, and they are the same; (3) that url is https://github.com/ORG/REPO or git@github.com:ORG/REPO with ORG one of NLH-OS, NLH-GOVERNANCE, NLH-NEDU-CORE (no user, port or query); (4) git reaches GitHub the default way: in the effective config (`git config --list --show-scope`) every entry under url, protocol, ssh, http, remote, core and credential is on a short allow list of harmless settings (Git's own `http.sslBackend` and `http.sslCAInfo` from the system config, `core.autocrlf` and the like, `remote.*.url/fetch/pushurl`, a plain or `gh auth git-credential` credential helper from the system or global config), and none of these variables is set: GIT_SSH, GIT_SSH_COMMAND, GIT_PROXY_COMMAND, GIT_CONFIG_*, GIT_DIR, GIT_WORK_TREE, GIT_EXEC_PATH, GIT_SSL_*, GIT_ASKPASS, SSH_ASKPASS, CURL_CA_BUNDLE, SSL_CERT_FILE, SSL_CERT_DIR, HTTP_PROXY, HTTPS_PROXY, ALL_PROXY (a machine behind a proxy pushes by hand); `include` and `includeIf` are followed by git itself, so what they load is checked entry by entry; (5) `git ls-remote` of that url (run as `git -C <repo>`, 25 s limit) can be read; (6) every commit the target does not have (by that ls-remote, not by local remote-tracking refs; merge commits and binary files read as text) holds no secret-like file name (.env, *.pem, *key*, id_rsa, *token*), no key-like added line and no key-like line in its commit message, and could be read in full (patch and messages up to 20 MB each). Key-like means one of: a GitHub token, a Slack token, an age secret key, a PEM private key, an Anthropic key, any other `sk-` key with a digit in it, an AWS access key id, a Google API key, a Telegram bot token, a literal value of 16 characters or more assigned to VAULT_KEY or api_key (any case, `-` or none for `_`), or a JSON Web Token; a name such as `process.env.API_KEY` is not a value. Lines are matched as text, so a key written another way is not caught: auto-push is a convenience, not a secret scanner; (7) the local gate `gate/hook.mjs`, unchanged, is run by the worker as for a `git push` typed by hand, of exactly that commit and branch; it is not told it is being asked, and no person is asked anything. It counts as a yes only when it exits 0 in time, prints nothing (the gate prints a line only to deny) and leaves its record for a push it let through (`push-<id>.json` in its state folder, read and then removed) for exactly that commit, branch, repo and folder, saying its rules were loaded and ran. A crash, a timeout, any printed line or a missing record is a no; (8) HEAD and branch did not move meanwhile (read again just before pushing; urls and settings read again too). Then the worker itself runs `git push --no-recurse-submodules --no-follow-tags --no-signed <that url> <sha>:refs/heads/<branch>`: the commit id that was checked, never HEAD, never force, with no question to anyone (the code goes to GitHub without a person saying yes; that is why it is off by default). When a secret, an unreadable patch, odd transport or two different urls stops it, Claude gets one line with counts and kinds only (never a file name); a network error or refusal is silent (one line in `~/.tinh-nlh/autopush/autopush.log`) and the next commit tries again. **Off by default:** it runs only on a machine that sets `NLH_AUTOPUSH=1` (exactly `1`; unset, `0`, `true`, ` 1` and anything else mean off, with no git, no network and no log). Turn it on only on a machine where Build writes code; never on a machine that holds real keys (personal data, production).
- machine schedules (Claude Code only): at session start `hooks/local-schedules-hook.mjs` reads, read-only, the scheduled tasks of the Claude desktop app (`claude-code-sessions/<account>/<organisation>/scheduled-tasks.json` in the app data folder) and tells Claude to pass name, when and on/off in the first `report_session` (`local_schedules`); never the prompt, a path or an environment variable. Checked on Windows; on macOS the app data folder is a candidate, not verified.

The plugin holds no secret and copies no rules or cells: everything is read from the system after sign-in. It creates no scheduled tasks; for a cell to work while Claude is closed, turn on a scheduled task or a backup machine.

## Data

The plugin stores nothing except for Loa: its launcher copy, read mark and last read time, seen ids, pending sends, told and held item ids for reminders (`tower-state.json`) live in `~/.tinh-nlh/speaker` on the machine; the key is encrypted with DPAPI (Windows) or kept in the Keychain (macOS), readable only by that account on that machine. The local gate keeps its cached rules, last passing test tree and recent blocks in `~/.tinh-nlh/gate`. Loa reads from `api.nlh.vn`; everything else goes through the connector at `mcp.nlh.vn`, under the user's own company account.
